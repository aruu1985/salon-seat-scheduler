# V0.12.14 月排班 PNG 截圖修正

基底：main 0364c33（V0.12.13）。獨立 fix/month-screenshot，不合併到店、同行或 Spark 分支。不改 Firebase、排班規則、篩選介面、預約卡或姓名功能。

## 根因證據

舊 captureScheduleScreenshot 在切換畫面後固定等待 900 ms，以 scheduleModal.outerHTML 加入 SVG foreignObject，直接交給 Image 解碼，再畫入 Canvas。HTML 序列化包含不符合 XML 的未閉合 input；Chromium 與 WebKit 都重現 image.onerror，DOMParser 顯示 input 與 div 標籤不匹配。正式提示只顯示「截圖失敗」，console 只有 Event，掩蓋了解析原因。這不是加長等待能解決的問題。

Git 歷史：dc18a20 原先只有截圖畫面切換；3635f7d 增加上述 PNG／分享流程，當時即使用同樣的 outerHTML。V0.12.12 的固定休修正只影響休假資料 fallback；V0.12.13 的 schedule.js 與 V0.12.12 完全相同。因此不能將此解析錯誤歸因於新稱謂或固定休；歷史裝置是否曾成功下載 PNG 無法從提交紀錄證明。

另有尺寸缺陷：舊圖只取 modal 的 viewport 寬高、固定 2 倍畫布，CSS 把月曆固定在螢幕內且 overflow:hidden，多人休假與月底內容可能被裁掉。改成合法 XML 雖可解碼，也不會自動解決這個問題。最小合法 foreignObject 在本次 WebKit 可正常輸出，沒有把所有 Safari foreignObject 誤稱為不支援。

## 修改方式

- 原按鈕／分享或下載流程保留；只替換圖片產生階段為 schedule-image.js 原生 Canvas。
- 先沿用現有 screenshotMode 月曆渲染，再取得 title、每個日期、目前篩選的完整休假姓名、顏色、半天說明及店況標示。不要讀取表單 outerHTML；不需外部截圖套件、外部圖片或 DOM-to-SVG。
- 文字量測、換行，依每週最高內容配置圖片高度；不依 viewport 或畫面上已省略的字串裁圖。日期、週幾與完整名字均入圖，不含控制項、toast、個人草稿標籤。
- 字型就緒後產生 PNG，移除無條件 900 ms 延遲。保留品婷既有描邊效果與人員原色。限制畫布為約四百萬像素、最大單邊 8192，降低 iOS 記憶體風險，仍為一張完整圖片。
- canShare 成功時維持系統分享；NotAllowedError（例如暫時使用者啟用已過期）改走原本下載路徑；使用者取消分享不當作產圖失敗。
- PNG 空白／失敗與逾時會回報失敗，不報成功。finally 恢復模式、篩選、個人模式、選取日期及捲動位置。取消期間不再輸出檔案，避免重複開始。
- console 只記階段、錯誤類別及允許清單中的固定錯誤碼，不含姓名、班表內容或正式畫面的程式堆疊。

## 驗證範圍

tests/schedule-image.py 使用合成 SDK、阻擋外網，實際下載 PNG，用 Pillow 重新開啟並驗證尺寸、完整日期、每名人員的繪字記錄／位置與實際像素／代表顏色；另人工查看實際設計師、技術師、全部模式圖片。包含 12/31 十五人同日休假、固定休＋額外休假＋明確改上班、下半天 14:30、店休、2028/2/29、2027/1。Chromium／WebKit 覆蓋 390×844、820×1180、1180×820、1440×1000。

故障模擬包含 PNG 編碼失敗、分享無權限轉下載、分享成功與取消、個人模式恢復；全程零測試班表寫入。日期兩階段、單人 CRUD／第二服務、現場承接提醒、固定休／稱謂單元與瀏覽器、版本資源更新另外回歸。

以上為瀏覽器／合成 SDK 模擬，不能當作 iPad Safari 實機驗收；實機仍需確認系統分享／下載、存入照片或檔案、正式十二月三個篩選與實際人數、取消分享後繼續編輯。正式網站驗證只讀取靜態版本／資源，不操作正式排班或客人預約。
