# V0.12.15 月排班三區篩選

以正式 main 78178f8（V0.12.14）為基底；不合併到店、同行、Spark 或其他候選分支。

## 原因

displayFilter 原本只用在月曆的 staffMatchesDisplay。左側 renderRoster 與右側 renderEditor 都產生全部職類，而且 setDisplayFilter 每次呼叫 renderAll，會重建表單。尚未觸發 change 的文字輸入可能被重建丟失。原欄位在 change 時會自動同步，直接隱藏正在輸入的欄位還可能因瀏覽器 blur/change 觸發非預期保存。

## 修正

- 左右兩區按職類 section 控制 hidden，中間仍沿用原篩選；共用 displayFilter 與 applyPersonnelFilter。所有人員主檔及排班仍完整保留於記憶體，並不篩掉資料來源。
- 篩選不再 renderAll 或重建一般當日編輯欄位，保留輸入節點、勾選及店況草稿。renderEditor 的職類 section 本身也帶正確 hidden，確保點選其他日期、快速設定或背景重繪仍正確。
- 只有焦點在右側人員欄位時，滑鼠按下篩選按鈕避免搶走輸入焦點；年月輸入等其他控制項仍可正常離焦。採用 mousedown 而非阻止 pointerdown，避免 WebKit 觸控點擊被取消。鍵盤操作維持按鈕原生功能。
- 未完成編輯且新篩選會隱藏該欄位時，保留原模式和完整輸入，提示先點欄位外空白處完成原有自動同步，或還原內容，再切換。包含只有空白差異或未完成時間的輸入；不替使用者代為保存或丟棄。
- 一般欄位已經觸發 change 的修改／既有待同步寫入仍遵循原自動同步，不會因篩選撤銷使用者先前的編輯。此功能只保證篩選本身不新增寫入。
- 整月個人草稿在新篩選仍包含該人員時繼續保留；若會隱藏該人員且有未儲存變動，提示先「儲存休假」或「取消」，不切換。乾淨的個人模式可退出回到原日期，清除舊的個人選取外觀。
- 明確按多人快速設定時只處理目前可見職類的已勾選人員；隱藏職類即使仍勾選也不會被修改。
- 更新說明文字及篩選按鈕 aria-pressed；保留原版型、顏色、休假算法與當日臨時出勤來源。

沒有改 Firebase 規則、結構、讀取／監聽、計費或正式資料。出勤與現場承接提醒不讀 displayFilter，因此不會因隱藏人員而減少人數。V0.12.14 Canvas 模組未修改，仍使用中間月曆篩選後的完整月份內容。

## 測試範圍

- tests/schedule-filter.py：合成 SDK、外網阻擋；反覆切三模式、左右職類與月曆一致、日期不變、固定＋額外休假、每日臨時上班、原出勤 snapshot 不變。核對欄位／店況節點與未完成內容保留、阻擋隱藏未儲存欄位或個人草稿、還原或完成編輯後可切換、乾淨個人模式正確退出、純篩選零寫入。另以明確操作驗證原 change 自動儲存與快速設定僅修改可見人員。
- Chromium 與 WebKit：390×844、820×1180、1180×820、1440×1000；平板／手機用 tap。窄螢幕沿用既有隱藏左側列表的版型，測試職類 section 狀態，不把隱藏按鈕的程式呼叫當成觸控驗收。
- tests/schedule-image.py：實際 PNG 下載／重讀與像素驗證，三個篩選、完整月底與多人休假、其他月份、分享／取消／失敗恢復；原 Canvas 檔案維持不變。
- 日期兩階段、單人新增／修改／刪除、第二服務、承接提醒及版本資源回歸。

以上為模擬瀏覽器與測試資料，沒有對正式 Firebase 寫入測試。iPad Safari 實機仍需驗收三區切換、未完成欄位提示、個人草稿、三模式分享及取消後續編輯。
