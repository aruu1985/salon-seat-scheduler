# V0.12.0 驗證紀錄

所有功能測試使用記憶體 Firebase mock，沒有正式 Firestore 寫入。Playwright Chromium 使用本機 `/usr/bin/chromium`；手機／平板是視窗與觸控模擬，未宣稱 Safari 或實機通過。

| 驗收 | 結果與證據 |
|---|---|
| 9／12／5 小時及延長營業 | 單元測試與三尺寸 UI：選項 18／24／10／20 個；另測 17 小時無固定最大值 |
| 依預約日期切換 | 單元測試、第二服務跨年與日期切換，使用該日期年曆 |
| 30 分鐘／9 小時方塊 | 三尺寸實際 DOM 高度為 1／18 格扣除原有內縮 |
| 晚開始不能超過打烊 | 15:00 開始 9 小時拒絕，表單保留，mock 寫入數不增加 |
| 舊預約保留時長 | 保存 9 小時後縮短店況到 5 小時，再開啟編輯仍為 9 小時；滾輪標示歷史原值 |
| 取消滾輪 | 滾到最大後取消，背後值未變；歷史超限值也未變 |
| 店休／不可預約／政府假日 | closed/noBooking/spring 單元測試；closed UI 拒絕儲存；政府日曆不納入店休推算 |
| 多段營業 | 課程／會議切開區間，最大取最長連續區間，跨會議預約拒絕 |
| 第二服務 | 獨立日期、時長、開始時間、超時拒絕、合法保存；跨年 14 小時及較短日期切換保留原值 |
| 三種尺寸 | 390×844、820×1180、1440×1000，全套功能與方塊測試通過 |
| 觸控、滑鼠、鍵盤 | Chromium CDP 合成 touchStart/Move/End 實際捲動；滑鼠 wheel；Home/End 等鍵盤；scroll snap 對齊 |
| 資料重新載入 | mock onSnapshot 重建及頁面 reload 後時長、卡片一致；未操作正式 Firestore 驗證 |
| 更新／快取 | 入口 build 與 version.json 相同；每個 JS/CSS 檔名符合其 SHA256；實際 Service Worker 退役舊 shell 快取 |
| 未儲存資料保護 | 新增預約、月底店況、年度店況開啟時偵測新版不重載且輸入保留；等待同步時更新按鈕停用 |
| 正式部署 | 另以 main commit 對應的 GitHub Pages workflow 與正式 HTTP 回應核對，結果於工作回報列出 |

既有人員顏色、指定符號、技術師、消費項目、月底排班及年度資料的模組未改動；主表單的項目勾選、指定及備註經店況 snapshot 更新仍保留。第二服務超出主卡片範圍時解除 paint containment，避免合法服務條被裁切。
