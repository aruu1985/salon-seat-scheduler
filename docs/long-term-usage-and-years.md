# V0.12.7 長期使用與未來年份檢查

基於正式 V0.12.6／bbcfab4，工作分支 feature/long-term-year-support。沒有合併同行、Spark原型、到店標記或備份工具分支。沒有修改 Firebase 正式資料、規則、schema、計費、索引、後端，沒有刪除、遷移或還原。所有寫入測試都只用合成資料與記憶體 SDK 模型。

## Firestore 實際程式盤點

| 項目 | 查核結果／處置 |
|---|---|
| 正常主畫面資料 | 預約只讀取選取日期 appointments，並非掃描全部歷史。員工、當日 staffing、當月 schedules、當年店況／年度事件、服務項目即時讀取 |
| 重複訂閱 | 原 staff.setDate 每次換日重掛月資料；schedule.setCurrentDate 每次換日重掛兩份年資料。現在同月／同年重用，變更或錯誤恢復才重新建立 |
| 相同來源不同模組 | 員工主檔與年度文件仍有不同模組各自消費。正常主畫面約10個應用層監聽、7個不同目標；SDK可能合併相同查詢，不能把每個回呼直接等同額外帳單讀取。本次未為追求數字大幅改成共用資料層 |
| 日期切換 | 當日預約與 daily staffing 仍正確解除並建立新監聽；保留跨裝置即時性，不用過期快取冒充即時資料 |
| 視窗關閉 | 原月排班3個、年度視窗2個監聽關閉後仍存活；現在明確解除。callback tickets 防止舊視窗／舊月份回呼覆蓋新狀態 |
| 重新載入 | 正常初始化、瀏覽日期、讀取不存在日期文件均不寫入。測得各年份與重載為0次測試寫入；未發現初始化會批次建立日期文件 |
| 多裝置 | 每台仍各自保持監聽，這是同步所需。明確按同步資料會執行原6項 server讀取；線上恢復也會重同步，不為省額度移除 |
| 排班儲存 | 原daily延遲儲存在執行時才取目前日期，快速換日可能寫錯；改為捕捉日期／職類／內容，在切換時送出。交易讀取當日最新資料，只替換該職類，保留其他職類與原有staffing欄位。這會在明確編輯時多1次交易讀取，優先保護資料 |
| 月份待存 | 切月／關閉前完成月排班待存內容；儲存失敗保留目前視窗，不假稱成功。慢速複製上月回應在目標月份已變動時拒絕套用，防止跨年寫錯 |
| 年度暫存混用 | 原monthly與annual共用store/legacy/govDays，跨年回呼可顯示錯年資訊。現在依年分隔，僅保留兩個視圖相關年份；店況修改交易讀取目標年度最新資料，只改使用者選取日期，保留其他裝置剛修改的日期 |
| 政府資訊 | 原每個日期／視窗都重新抓來源，現在同年併發合併、成功快取24h、失敗退避10min、8秒請求逾時。這是HTTP／本機快取，不是Firestore集合 |
| 全歷史管理操作 | 危險操作頁仍全量讀取appointments collectionGroup、trash與auditLogs；匯出／全部管理需要完整資料，本次不偷偷限筆數。歷史越多，該頁讀取／記憶體成本越高；日常按日期看板不會因此掃全庫 |
| 自動刪除 | 移除 loadDangerData 讀取流程中的 purgeExpiredTrash 呼叫，避免只是開管理頁就刪正式文件。過期垃圾桶仍不列為可復原，但資料保留；日後任何清理須另獲授權 |

## 年份支援

原預約、導航、排班與Firebase路徑大多已按 YYYY-MM-DD／YYYY-MM／YYYY 計算，沒有2027截止。修正年度輸入原本2020～2100的任意範圍為現有四位年份格式1000～9999，採通用閏年／月天數計算，不每年改碼、不預建未來日期文件。

實測2027、2028、2029、2050、2100、2400；2028-02-29、2400-02-29合法，2100年2月只有28日，2028-12-31→2029-01-01正確。模擬裝置今天為2028-02-29時，今天／前一天／明天正確。不同年相同預約ID仍按日期完整路徑隔離。

固定休維持既有操作：管理員主檔設定星期，明確按「一鍵套用固定休」才寫月底例外；每日臨時排班可覆蓋。沒有在瀏覽未來年份時自動生成或覆寫排班。

## 政府假日來源與故障

- 正式資料來源仍為行政院人事行政總處資料集 https://data.gov.tw/dataset/14718。
- 依西元轉民國年份尋找官方鏈結，限制HTTPS官方網域，檢查轉址、CSV欄位、合法Gregorian日期與快取年份／來源；拒絕任意第三方連結與錯年快取。
- 程式不推算未公布假日。取不到資料時明示「可能尚未公布或暫時無法連線」，不把連線失敗斷言為未公布。
- 失敗優先使用有效的上次官方快取，再用隨版官方快取；不以較舊內建資料蓋掉已取得的有效快取。
- 目前隨版官方快取只有2026。未來年份若有官鏈且可連線會自動載入；受來源公布／CORS／網路限制時不保證可取得。年份功能不需每年改碼，但不保證未來每年都有離線官曆。
- 政府資料只顯示參考，不寫入FireStore、不自動改本店營業時段或店休。官方資料缺失不阻止預約／排班使用。

## 仍需注意

- Spark免費額度與其他裝置／備份共用，裝置多或頻繁強制同步會增加讀取。請以Firebase Console真實用量判斷，不以本報告的SDK計數替代。
- 全歷史管理讀取、垃圾桶／稽核資料累積、本機快取容量均會隨長期使用增加；本輪不刪歷史、不做清理／歸檔／schema變更。每份Firestore文件仍有1MiB限制，長備註與大型月／年設定須留意。
- 本輪修正店況與臨時角色交易，但沒有新增跨座位的全日原子佔位鎖；兩裝置同時建立不同ID搶同座位，仍是原正式版的併發限制。月排班整份exceptions儲存亦仍可能有同月同時編輯互覆風險，未宣稱已解決所有多人寫入問題。
- 正式權限／安全規則仍沿用原版本，未做管理端規則審計，也未升級Blaze。
- 請用iPad Safari驗收日期、排班修改與同步；任何正式資料清理、規則或結構變更都另行確認。

## 重現

```sh
python -m http.server 18776 --bind 127.0.0.1
```

另一終端執行 `node tests/government-years.cjs`、`python tests/long-term-years.py`、`python tests/long-term-crud.py`、`python tests/long-term-subscriptions.py`。WebKit用HEADER_ENGINE=webkit與既有Playwright引擎路徑；原測試支援SALON_TEST_BASE=http://127.0.0.1:18776/，sync另支援SALON_TEST_DATE=2028-02-29。正式資料不能作為測試fixture。
