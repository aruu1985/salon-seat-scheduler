# V0.12.1 重整及資料同步驗證

## 已確認的程式缺口

- 重整事件有綁定 `refreshData`，原先會對該日期的 appointments 使用 `get({source:'server'})`，不是單純重繪記憶體；但只更新預約，沒有重讀排班、當日人員及店況，成功／失敗提示也只在頂部小字。
- 即時監聽內呼叫舊版 v06 自動匯入。空快照可能把本機舊資料重新寫回雲端，匯入失敗也可能中斷這次快照呈現。新版本完全移除讀取路徑中的自動回寫，不刪除本機或正式資料。
- 舊回覆只比對日期字串，A→B→A 時無法辨識第一次 A 的延遲回覆；監聽失敗、斷線恢復與初始化認證失敗缺乏一致恢復。
- 編輯保存原本直接 set，沒有比較使用者開啟表單時的原始文件，可能覆蓋其他裝置的新資料。

## 修正原則

沿用現有 Firestore onSnapshot。切換日期解除舊監聽，用生命週期序號排除舊回覆；重整以唯讀伺服器讀取 appointments、staff、日期 staffing、月排班、年度 storeCalendar 與 legacy annualCalendars，全部完成才顯示「已更新」。離線、快取回覆、待寫入資料、任何讀取錯誤或逾時皆不回報成功。重整不呼叫網頁 reload，程式版本更新仍交由既有 version-update.js。

較新的監聽事件優先於較慢的手動讀取；重整及快照不套用今日營業驗證，也不改寫歷史預約。既有人員、店況監聽加上日期防護，年度營業監聽只保留主日期與第二服務所需年份。

使用既有文件內容（包含既有 updatedAt）計算記憶體指紋，透過 Firestore transaction 比對目前文件，拒絕較舊版本及已刪除文件的覆蓋。無新增 schema，未執行資料遷移。失敗時表單及輸入保留，顯示同筆資料已變更的提示。

## 執行測試

所有功能測試均使用隔離 Firebase SDK mock；不連線正式 Firestore，不執行正式資料新增、修改或刪除。跨裝置為兩個獨立瀏覽器 context，以模擬伺服器事件配送到既有 onSnapshot 回呼，沒有在應用程式另外建立輪詢同步系統。

| 驗收 | 測試結果 |
|---|---|
| 昨天、今天、未來日期重整 | 三種尺寸均通過，保留日期；6 個所需資料來源均以 server 讀取 |
| 排班、店況重新呈現 | 重整後顯示新的到班時間、技術師及延長營業時間 |
| 跨頁面新增、修改、刪除 | 另一 context 經快照自動顯示、更新、移除，不需按重整 |
| 跨頁面調整時間、座位 | 拖放路徑保存後，另一 context 的卡片位置同步 |
| 舊資料不回填 | 空快照搭配 v06 本機舊資料，沒有任何資料寫入或舊卡片重現 |
| 切換日期與監聽釋放 | A→B→A 延遲回覆被忽略；有效 appointments listener 始終只有一個 |
| 慢速手動回覆 | 較新的同日期即時快照不被較舊讀取結果取代 |
| 斷線／錯誤 | 任一所需讀取失敗或離線均顯示「更新失敗，請重試」，後續快照不假報重整成功 |
| 網路恢復 | online 後重新伺服器讀取；初次認證失敗也可不重載重試 |
| 監聽終止 | 成功重整後恢復一個監聽，後續事件可正常顯示 |
| 保護草稿／編輯衝突 | 背景快照、手動重整保留輸入；另一 context 保存後，舊版本交易拒絕寫入 |
| 手機、平板、電腦 | 390×844、820×1180、1440×1000 Chromium 模擬通過；非實機驗證 |
| 卡片格數與衝突 | 既有時長、格數、卡片相鄰／衝突、縮放回歸測試通過 |
| 安全程式更新 | 既有資源雜湊、Service Worker 退役及編輯中禁止版本重載測試通過 |

命令：`node tests/data-sync.cjs`、`node tests/hours.cjs`、`node tests/seat-layout.cjs`、`python tests/sync.py`、`python tests/browser.py`、`python tests/interaction.py`、`python tests/overlap.py`、`python tests/update.py`。瀏覽器測試使用本機 8765 HTTP server。
