# V0.12.9 服務人力提醒

本功能是可繼續儲存的人力警告，不是搶位交易防護、服務階段模型或設計師個人接單限制。不更動 Firestore schema、安全規則、索引、計費或既有資料。從正式 V0.12.8 / 0961890 獨立開發，未合併同行、到店或 Spark 候選分支。

## 人力及客人

- 共用 `SalonStaff.entryFor`：當日臨時異動優先，其次月底排班例外，最後沿用既有正常班預設。固定休仍依既有「套用固定休到月排班」操作；若固定休當天沒有明確的每日／月排班紀錄，視為出勤未確認並提醒資料不完整，不偷偷更改主畫面既有出勤規則或算成正常出勤。
- 啟用中的 designer + technician（助理）；以員工 ID 去重。重複編號的不同文件標示資料不完整；停用、休假、請假不計。
- 正常班依該日實際營業區間；late/afternoon 讀實際 `time` 或 `workStart`，early/morning 讀 `time` 或 `workEnd`，特殊上下班讀 `workStart/workEnd`。不寫死半天班切點。休息區間不計；到班含起點、下班不含終點。
- 缺主檔、孤立排班識別碼、未知班別、時間缺漏／矛盾、跨夜班別、尚未同步／離線／排班儲存未完成／失敗，都提示「人力資料不完整」。不將未知人員當成零人或已確認正常。
- 每個有效主預約 ID 算一位，採主預約 `[startTime, startTime + duration × 30 分鐘)`。跨所有座位及不指定客人；第二服務不另增加一位。此版不另外推算主預約區間之外的第二服務在店人數；第二服務的營業時間驗證照舊。
- 修改以新資料取代相同 ID；已刪除快照不存在，取消／刪除旗標的原始資料不計。沒有修改原始儲存內容。

## 提醒與儲存

檢查主預約全部 30 分鐘區間，亦在實際到離班或預約起訖切點切分（例如 14:15），避免半小時中途人力變化被漏掉。相鄰超額區間合併，變動人數以範圍顯示。

新增、編輯及拖曳調整時間均會檢查。返回調整不寫入、保留草稿；仍要預約後，重跑營業時間、座位、日期及人力檢查；若人力報告改變，需重新確認。提醒前選定的座位不會在確認後偷偷改配；若已被占用，保留草稿並要求返回調整。相同預約的原始版本指紋仍交給既有 Firestore transaction 驗證，不能用較新指紋偷偷覆蓋其他裝置。

只讀現有即時監聽結果，沒有新增長期監聽、資料庫查詢或寫入。既有三個人員監聽開啟 metadata 回呼，以分辨快取／待寫資料；不增加監聽目標。最後一次判斷之後其他裝置仍可能儲存，本提醒不保證全域原子名額或解決跨裝置搶同一座位。

## 隔離測試

- `node tests/service-capacity.cjs`：人數、半天班、早退晚到、特殊時間、半開區間、第二服務、修改取代、合併、取消、缺資料與去重；無資料修改。
- `python tests/capacity-warning.py`：Chromium 390/820/1440；WebKit 使用 `HEADER_ENGINE=webkit`。只用合成 SDK 資料、阻擋外網：返回保留／零寫入、繼續存獨立預約、修改不重算、同筆遠端修改防覆寫、未知人力與重新確認、提醒後指定位置被占用即拒絕（即使其他位置仍空）、監聽數不增加。
- `tests/sync.py`：雙瀏覽器模擬新增／修改／刪除／拖曳、版本衝突、日期切換、離線恢復與監聽解除。
- 既有單元、CRUD、年度／排班／店況、主畫面、同步按鈕及版本更新測試。

以上為合成資料與模擬瀏覽器驗證，不是 iPhone/iPad Safari 實機或正式 Firebase 寫入驗收。正式部署只驗證靜態版本與資源，不以正式客人資料做測試。部署後仍需 iPad 實機驗收觸控、短／長提醒捲動與實際班表設定。
