# V0.12.11 現場承接提醒 A 方案

基於正式 V0.12.10（64711a6）獨立開發。保留兩階段日期選擇器；不合併同行、Spark、到店或備份候選分支。僅前端顯示與判斷，不新增 Firestore 欄位、集合、索引、規則、後端或計費。

## 每個時段的基準

可靠資料下，基準 = min(主要區 6 格, 該時段確認在班的設計師＋技術師／助理)。12 個實體座位仍沿用既有排程與容量限制，6 是一般承接提醒基準，不是禁止預約的名額。

沿用每日臨時異動 > 月排班 > 既有正常班預設。正常班依當日營業區間；晚到、下半天、早退、上半天與特殊上下班讀取現有 time/workStart/workEnd，不寫死半天班切點。排除休假、請假、停用、尚未到班及已下班；員工 ID 去重，編號／識別矛盾者不算成確認出勤。

每個有效主預約 ID 算一位，所有座位與不指定客人均計入。沿用主預約半開區間 [startTime, startTime + duration×30 分鐘)，第二服務不另加一人；此版不另推算主預約區間外的第二服務在店人數。掃描每個 30 分鐘時段，並於實際到離班及預約起訖切點再切分，避免漏算例如 14:15 的變化。

## 不完整資料

- 未知班別、缺實際上下班時間等，不當作正常在班。V0.12.12 起固定休依共同規則直接判休；明確的月排班或每日上班例外優先，不再把固定休當成未確認。
- 已確認人力足以承接且客人不超過六位：不因其他人員資料不明而跳窗。
- 已確認人力不足、另有人員未確認：顯示「可能需要額外承接／人力待確認」，確認人數是下限，不宣稱確定不足。
- 全部班別未知、無主檔或人力尚未同步：六位以下只在排班資訊列下方提供文字提示，不做精確人力比較。若預約快照可靠且可確認超過六位，仍依主要區基準提醒，確認在班顯示「待確認」。
- 預約快照未完成同步：非阻斷提示，不用舊快照假裝精確比較。資料恢復後沿用既有即時監聽更新提示。
- 已讀取的有效預約若超過基準，但尚有起訖資料無法判定的舊預約：以「目前可確認預約」及待確認措辭提醒，不捏造完整客人數。

## 新增與修改

新增時包含待新增客人。修改／拖曳時，先排除同一 ID，再以修改後資料取代；只檢查新區間超出原區間的部分。修改姓名、電話、備註、項目文字、座位或縮短／內縮時段，沒有增加時段負載就不重複提醒。原預約起訖損壞而無法比較時，只顯示待確認提示，不猜測負載增加；既有資料驗證仍執行。

連續需提醒的區間合併，變動人數與門檻用範圍顯示。一次儲存嘗試最多一個整合彈窗。返回不寫入並保留草稿；繼續後重新讀取當下記憶體快照，仍重跑營業時間、原先座位與資料版本檢查。確認期間位置被占用就保留草稿並要求重試，不偷偷改配座位。人力提醒永遠不自行縮短、取消、移動預約。

此提示不是名額鎖定，也未解決不同裝置新增同座位的原子競爭；其他裝置仍可在最後檢查後變更。沒有新增監聽或資料查詢，利用既有排班／預約回呼與儲存狀態更新提示。
